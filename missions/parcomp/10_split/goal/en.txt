Mission goal
============

Until now, we have considered either multiple files or multiple
commands. But sometimes, we will want to process a single
file faster. The `split` command was originally written to
split large files into multiple smaller ones, but it can
actually run programs on each part, called "filters", rather
than saving them to files.

The goal of this mission is to speed up the processing of
file `d.txt` by `./upper.sh` using the `split` command and its
`--filter` argument.

Here again, use the `time` command to measure how long it
takes.

Useful commands
===============

split --number XX --filter COMMAND FILE
  with these arguments, `split` will split FILE into XX pieces
  and feed each as standard input to COMMAND


Remarks
-------

The `--filter` argument only exists in GNU split, the version
installed on Linux. On macOS, it is provided by Homebrew's
coreutils package (`brew install coreutils`) under the name
`gsplit`; GameShell makes `split` point to it for you.

The `split` command will bufferize the outputs for the sake
of performance, but for small test cases, you should deactivate
it in order to be able to perceive the difference with the case
where the script is called on the whole file. Use `--unbuffered`.

The --number accepts a specific notation to denote round-robin
distribution of the lines to the scripts, which you should use here:
--number r/4 so that four instances of `upper.sh` are started,
and fed each line of the `d.txt` file.

Here, as in the previous mission, the input will be fed through
stdin, so the output must be redirected explicitly to a file.
